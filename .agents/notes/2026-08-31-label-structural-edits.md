# 决策：断句修正并入 label 面板（m/x/d 命令）（2026-08-31）

已实施

## 问题

用户反馈"断句有问题，原视频可能读太快"：快语速下标点模型会并句（run-on）或碎句，自动断句无法完美。

## 调研

实测 FunASR 另一条断句路线（同视频对比）：

- 当前 `punc_segment` 模式（按标点断句）：18 段，带标点，粒度较细
- `spk_mode="vad_segment"` + `max_end_silence_time=300`：14 段，但大面积并句（9.47-14.24s 混 4 句）、丢标点、把"一个人才有问题"拦腰切断

结论：自动断句已无更优参数可调，残余错误人工修。

## 决策

断句修正进 label 面板（第 2 步人工校对本就是兜底点），新增三个命令：

- `m <编号>` 合并连续句子：文本拼接、时间取并集、说话人取第一个非空；非连续编号报错不动
- `x <编号> <A>|<B>` 拆分：切分点默认按两段字数比例估算，可 `x <n> <秒> <A>|<B>` 显式指定；两半继承原说话人（改人随后 `=` 命令）
- `d <编号>` 删除：清识别幻觉/噪声段
- 结构改动后 id 按位置重排（id == 位置），避免 run 的 segment_id 冲突
- 撤销改为整表快照（原先只存 speaker 批次），改人/合并/拆分/删除统一可撤
- 错字修正不进面板：CLI 单行改中文长句体验差，直接编辑 02_labeled.json 的 text 更自然

## 验证

- 新增 6 组用例（合并/区间与非连续拒绝/比例拆分/定秒拆分/删除/结构撤销），全量 117 passed
- 真实视频面板实测：`m 5-7` 合并三段碎句、`x 3` 在 5.987s 拆分两人并句、`w` 保存均正常

## 追加（同日）：m 可带文本 + 识别期静音细切

用户进一步明确：碎句没关系，碎是修标点的最细单元；要求识别时在"明显有空隙"处就切开。

- `m` 支持可选合并后完整文本（`m 23,24 有问题，找药师。`），合并顺带修标点
- `asr_funasr.py` 新增 `_split_segments_by_silence`：diarize 路径在 sentence_info 基础上，
  用 result["timestamp"]（字级）在句内静音 ≥200ms（`split_silence_ms`）处细切，说话人继承；
  对齐安全阀：句窗口内时间戳数 ≠ 句非标点字符数时该句不切
- 探测实证：sentence_info 的 key 是 "text"（不是 "sentence"，靠 fallback 才工作）；
  每句窗口重叠对齐精确（字数=时间戳数）
- 缓存键升 v3
- 实测 31s 视频：18 → 24 句（"我们这里是|药店|买酒到隔壁""京都念慈庵|你个人才|有问题"等全部按空隙切开）
- 最终 02_labeled.json：23 句（合并"有问题，找药师。"），SPEAKER_0: 8 / SPEAKER_1: 15
- 全量 120 passed / 3 skipped
