# 决策：工作流收敛 — 三条路径 + 阶段编号目录 + label 命令式面板（2026-08-31）

已实施

## 问题

用户反馈"不知道按什么顺序用、命令组合太多、中间产物乱放不知道改哪个"。

根因三个：
1. 文档平铺全部能力（run 一步 / transcribe+run / diarize / label / TOML...），没有推荐路径。
2. 中间产物随机命名散落在 output/ 平铺目录（transcript_v2 / 修正 / 修正版 / 日志）。
3. label 初版是"逐句遍历"式交互，句子多时 O(n) 太累。

## 决策

### 三条使用路径（文档以路径组织，不再平铺）

- 路径 A 单人：`run` 一条命令
- 路径 B 多人：`transcribe --diarize` → `label` → `run --segments-json`
- 路径 C 改台词重跑：编辑 02 后只跑 run

### 阶段编号目录约定（默认值，非强制）

```
output/<输入名>/
  01_transcript.json   # 机器产
  02_labeled.json      # 人工产（唯一要人工碰的文件）
  03_成品.mp4          # 成品
  .videodub/           # 报告/中间产物
```

三个子命令默认输出全部遵循：transcribe → 01，label（输入为 01_* 时）→ 02，run → 03。
`-o` 永远可覆盖；workspace 跟随输出目录自动归位，无需额外改动。

### label 改为命令式面板（解决"句子多时逐句过太累"）

- 启动显示：按说话人分组的编号概览 + 全部句子明细
- 修改语法：`13=0`（单句）/ `13,17=0`（列表）/ `10-18=0`（区间）/ 混合
- `p <编号>` 用 ffplay 试听原视频对应片段（新增 `--media` 参数）
- `l [编号]` 重看列表（可局部）、`u` 整批撤销、`w` 保存、`q` 放弃（有修改时确认）
- `--apply` 稀疏回填保留（脚本化场景）

### 组件化不破坏

- 不做向导式一条龙命令（会把识别/校对/渲染焊死，破坏"想只改 02 重跑"的场景）
- 分层不动，只改三个 CLI 的默认输出逻辑（各 ~5 行）
- 现有 output/ 散文件按约定归位到 `output/8月31日/`
