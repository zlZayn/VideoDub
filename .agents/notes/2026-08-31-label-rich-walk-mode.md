# 决策：label 面板改逐句审阅流 + rich 排版（2026-08-31）

状态：生效

## 问题

label 原交互为命令式面板：启动打印全部句子刷屏（几十到上百行）、无颜色排版、
改人必须敲完整命令（`13=0`）、用户反馈"实在是太难用了"。

## 调研

- 原交互测试全量通过，命令语法（改人/合并/拆分/删除/试听/撤销）合理，问题在呈现与节奏
- rich 15.0.0 已在环境内（此前未声明依赖，也未用于本命令）

## 决策

- 交互改为逐句审阅流：启动只显示分组概览 + 光标句附近窗口（上下各 3 句），光标句 `▶` 高亮
- 回车 = 下一句；直接按 `0/1/2` 改当前句说话人并前进（最常用操作一键完成）
- 多位数 = 定位跳转；`l <编号>` 跳转 · `l` 重看概览
- 原有命令全保留（`13=0`、`m`/`x`/`d`/`p`/`u`、`w`/`q`），`?` 展开完整帮助
- rich 排版：说话人分色（人0 青 / 人1 品红 / 未标灰）、分组概览 Panel、底部状态条
- 撤销栈升级为 (快照, 光标) 组合，回滚后光标回到操作前位置
- rich 声明为 pyproject 核心依赖（`rich>=13.0`）

## 替代方案（强制）

- 方向键上下移动光标：需要 raw 终端模式，与现有逐行 input 解析冲突，且测试无法模拟方向键
- 启动仍打印全部句子仅加颜色：治标不治本，刷屏依旧
- 单数字既是"跳转到第 N 句"又是"指派说话人 N"：语义冲突（`13` 是跳转还是改人 13），
  选"多位数=跳转、单数字 0-9=指派当前句+前进"，跳转另有 `l N` 明确语法

## 影响

- 测试新增 5 组用例（审阅流改人前进/空行前进/跳转/含 0 指派/撤销回滚），全量 126 passed / 3 skipped
- 架构文档 3.1 与 tests/README、src/videodub/README 的 label 描述同步更新
- 控制台 pip 运行环境需 `rich>=13.0`（uv sync --all-groups 自动装）
